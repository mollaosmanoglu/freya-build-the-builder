Build a Freya phone agent for the bank brief {brief}. The bank's tool API for this brief is {api}.

## Goal
Every customer the bank could send must pass all three runs of the same test. A customer who passes once and fails once counts as a failure, so reliability matters more than cleverness.

## Sources of truth
- The brief and the tool API file are the only sources for rules, tool names, fields and allowed values. Take nothing from memory, from another brief, or from files left by earlier builds.
- If the brief is raw material (a mail, a memo, a code list), first turn it into a numbered list of rules and decide what overrides what. Build from that list.

## How Freya works
Read `docs/workflow-format.md`, `docs/tools-and-code.md` and, for testing, `docs/api.md`. `freya.save_workflow(slot, workflow)` creates or updates the workflow, publishes it and returns `workflow_id` and `agent_id`. Write the workflow to `out/`.

## Design
- Everything the brief states as a fixed rule (dates, amounts, limits, retries, which outcome follows which tool result) belongs in code and in transitions on tool results, not in prompts. The model should only hold the conversation.
- When a tool call fails, the agent says so. It never tells the customer something is recorded when it is not.

## Verification
- Write a test customer for each rule in the brief. Practice customers exist only for Briefs A and B: `python3 tools/run_cases.py <agent_id> --brief A|B [--reps N]`. For any other brief, talk to the agent with `POST /api/v2/chat/message`.
- Test with one run while you iterate. Before you finish, check with 3 runs. Finish only when every customer passes 3 of 3, or when the time is nearly up.

## Budget
You have 30 minutes in total and one test run takes 3 to 11 minutes. Save a working version early and improve it from there. Run tests in the foreground and wait for them: the builder stops when you stop.
Finish with one line: `workflow_id`, `agent_id`, and the result of the last 3-run check.
